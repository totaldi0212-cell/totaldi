# GEM 관리자

이 저장소의 GEM 시스템을 관리한다. GEM은 `gems/<이름>.gem.md` 파일 하나로 정의되고,
`./scripts/gem.sh sync` 가 이를 `.claude/skills/gem-<이름>/SKILL.md` 로 빌드하면
그때부터 클로드가 대화 중에 **자동으로** 그 역할을 꺼내 쓴다.

## 목록 보기

```bash
./scripts/gem.sh list
```

## 새 젬 만들기

사용자가 새 젬을 원하면, 템플릿을 그냥 던져주지 말고 **먼저 아래 4가지를 물어본다.**
(사용자가 이미 설명에 답을 다 담았다면 묻지 말고 바로 만든다.)

1. **무슨 일을 반복하나요?** — 실제 업무 시나리오
2. **어떤 사람이 해주면 좋겠나요?** — 역할/경력/관점
3. **결과물 형식은?** — 표, 이메일, 불릿, 보고서 등
4. **절대 하면 안 되는 건?** — 금지 사항

그 다음:

```bash
./scripts/gem.sh new <영소문자-이름>
```

생성된 `gems/<이름>.gem.md` 를 편집한다. 작성 원칙:

- `description` 이 가장 중요하다. 클로드는 **이 문장만 보고 자동 호출 여부를 판단한다.**
  사용자가 실제로 입력할 법한 표현("메일 써줘", "요약해줘")을 직접 넣어라.
- `## 역할`, `## 작업 지시`, `## 지켜야 할 규칙`, `## 출력 형식`, `## 예시` 를 모두 채운다.
- 규칙은 추상어("좋게 써라") 대신 검증 가능한 문장("5문장 이내", "느낌표 금지")으로 쓴다.
- 출력 형식은 뼈대를 코드블록으로 그대로 박아두면 재현성이 크게 올라간다.
- 예시를 최소 1개 넣는다. 예시 하나가 지시문 열 줄보다 강하다.

마지막에 반드시 빌드한다:

```bash
./scripts/gem.sh sync
```

빌드 후 사용자에게 "새 세션부터 자동으로 적용된다"고 알려준다.

## 고치기 / 지우기

```bash
./scripts/gem.sh show <이름>     # 정의 확인
# gems/<이름>.gem.md 를 편집한 뒤
./scripts/gem.sh sync            # 재빌드

./scripts/gem.sh remove <이름>   # 젬 + 빌드된 스킬 함께 삭제
```

## 주의

- `.claude/skills/gem-*/SKILL.md` 는 **자동 생성물**이다. 직접 고치지 말고 항상 `gems/` 원본을 고친 뒤 sync 한다.
- 젬 이름은 영소문자·숫자·하이픈만 쓴다.
- 젬을 만들거나 고친 뒤에는 변경된 파일을 커밋하라고 사용자에게 안내한다.
