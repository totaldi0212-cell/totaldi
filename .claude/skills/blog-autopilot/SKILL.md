# 블로그 자동 생산 파이프라인

하루 N편(기본 3편)의 네이버 블로그 원고를 키워드 선정부터 완성 원고까지 만든다.
**문체·구조 규칙은 전부 `gem-blog-writer` 스킬을 그대로 따른다.** 이 스킬은 "공정"만 다룬다.

## 전제

- 출력은 `posts/YYYY-MM-DD/` 아래 마크다운 파일.
- **네이버 블로그에 자동 업로드는 하지 않는다** (네이버가 외부 글쓰기 API를 열어두지 않음).
  사용자가 복사해 붙여넣을 수 있는 형태로 만드는 것까지가 이 스킬의 일이다.
- 사용자에게 시작 여부를 되묻지 않는다. 훅이 `auto` 모드로 불렀다면 바로 시작한다.

## 1단계 — 키워드 브리프 확보

```bash
cat posts/$(date +%F)/_keywords.md 2>/dev/null || python3 scripts/keyword_radar.py --out posts/$(date +%F)/_keywords.md
```

브리프에는 테마·대상 독자·시드 키워드 3줄이 들어 있다.
**시드는 출발점이지 제목이 아니다.**

## 2단계 — 시드를 실검색 롱테일 키워드로 좁힌다 (편당 웹 검색 2~3회)

각 시드마다:

1. 시드로 검색해 **지금 사람들이 실제로 궁금해하는 각도**를 찾는다.
   ("국민연금 조기수령" → "조기수령하면 얼마나 깎이나", "건보료 때문에 손해인가")
2. **제도·통계·가격은 반드시 검색으로 최신 수치를 확인**한다. 기억에 의존하지 않는다.
   연도, 금액, 요율은 특히 자주 바뀐다.
3. 확정 키워드는 **2~4어절 롱테일**로. 단일 명사(예: "연금")는 경쟁이 너무 세다.
4. 검색으로 확인한 **구체 수치 2~3개 + 출처**를 확보한다. 이게 글의 뼈대가 된다.

확인 못 한 수치는 **본문에 쓰지 않는다.** 글 끝 `[확인 필요]`로 뺀다.

## 3단계 — 중복 회피

```bash
grep -rh '^제목:' posts/ 2>/dev/null | tail -40
```

과거 제목과 각도가 겹치면 **각도를 틀거나 다음 시드로 넘어간다.**
같은 키워드라도 "방법"과 "실패담"은 다른 글이다.

## 4단계 — 집필

`gem-blog-writer`의 규칙 전체를 적용한다. 특히:

- 블랙리스트 표현 0건
- 10자 미만 짧은 문장 15% 이상, 1문장 문단 2개 이상
- 대상이 `60대 이상`이면 문장 35자 이내 + 번호 순서 안내 + 쉬운 말
- 구체적 숫자·시간·금액을 넣되 **검색으로 확인한 것만**

### 개인 경험 처리 — 중요

자동 생성이므로 **사용자의 경험을 지어내면 안 된다.**
"제가 작년에 조기수령 신청해봤는데"처럼 있지도 않은 일을 쓰지 말 것.

대신 이렇게 쓴다:
- 관찰형: "주변에서 이 경우를 자주 본다", "상담 사례를 보면"
- 조건형: "만약 55세에 시작한다면 계산은 이렇게 된다"
- 사용자 실제 경험이 들어가야 좋은 자리에는 `[여기에 본인 경험 한 문단 — 예: ○○]` 표시를 남긴다.

이 표시는 편당 **1~2개**만. 사용자가 채워 넣으면 글의 급이 올라간다.

## 5단계 — 저장

파일: `posts/YYYY-MM-DD/01-키워드슬러그.md` (번호는 01, 02, 03)

형식:

```markdown
---
날짜: 2026-09-16
테마: 노후 연금
대상: 60대 이상
확정키워드: 국민연금 조기수령 손해
플랫폼: naver
상태: 초안
---

제목: (28자 내외)

(본문)

...

#해시태그 #10개이상

---
[출처]
- 항목 — 기관/매체, 기준 시점, URL

[확인 필요]
- (검증 못 한 수치)

[자체 점검]
(gem-blog-writer의 점검표)
```

## 6단계 — 사용자에게 보고

글 전문을 채팅창에 도배하지 않는다. **표 하나로 요약**한다.

```
오늘 3편 완료 — posts/2026-09-16/

| # | 제목 | 대상 | 키워드 | 글자수 |
|---|------|------|--------|--------|
| 1 | ... | 60대+ | ... | 1,940 |

본인 경험 채울 자리: 4곳 (각 파일의 [여기에 본인 경험] 표시)
확인 필요 수치: 1건 (2번 글)

바로 볼 글 번호를 말씀해주시면 전문을 띄워드립니다.
```

그리고 마지막에 한 줄: **"네이버 블로그에는 직접 붙여넣으셔야 합니다."**

## 7단계 — 커밋

```bash
git add posts/ keywords/used.log && git commit -m "posts: YYYY-MM-DD 블로그 3편"
```

사용자가 git을 안 쓰는 상황이면 생략하고, 파일 경로만 알려준다.

## 실패 시

- 웹 검색이 막혔다면: 검증 가능한 수치가 필요 없는 **경험·방법론 중심 주제**로 각도를 튼다.
  (예: "국민연금 수령액 계산" 대신 "은퇴 첫해에 사람들이 흔히 하는 실수")
  그리고 사용자에게 "수치 검증 없이 썼다"고 명시한다.
- 키워드가 바닥나면 `keywords/bank.json`에 추가하자고 제안한다.
