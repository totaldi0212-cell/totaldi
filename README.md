# totaldi — 클로드용 GEM 시스템

구글 제미나이의 **Gem**(맞춤 AI 역할을 저장해두고 반복해서 쓰는 기능)을
클로드에서 그대로, 그리고 조금 더 강력하게 쓰기 위한 저장소입니다.

핵심 차이 한 줄: **제미나이 Gem은 골라서 쓰고, 여기 GEM은 알아서 튀어나옵니다.**
"이 메일 좀 써줘"라고만 해도 클로드가 `email-writer` 젬을 스스로 찾아 적용합니다.

---

## 1분 사용법

```bash
./scripts/gem.sh list            # 어떤 젬이 있나
./scripts/gem.sh new my-gem      # 새로 만들기
# gems/my-gem.gem.md 편집
./scripts/gem.sh sync            # 빌드 → 이때부터 클로드가 자동 인식
```

클로드 대화창에서는 이렇게도 됩니다.

- `/gem` — 젬 목록 + 관리 메뉴
- `/gem-new 이름` — 대화로 질문 받아가며 젬 설계
- 그냥 "젬 만들어줘" 라고 해도 됩니다

---

## 구조

```
gems/                       ← 여러분이 관리하는 원본 (이것만 고치면 됨)
  _template.gem.md
  email-writer.gem.md
  report-summarizer.gem.md
  meeting-notes.gem.md

.claude/skills/gem-*/       ← sync가 만드는 자동 생성물 (직접 고치지 마세요)
.claude/skills/gem/         ← 젬을 만들고 관리하는 메타 스킬
.claude/commands/           ← /gem, /gem-new 슬래시 명령
scripts/gem.sh              ← 관리 CLI
```

동작 원리는 단순합니다. 젬 파일 하나 = 클로드 스킬 하나.
`sync`가 `gems/*.gem.md`의 frontmatter와 본문을 읽어 `.claude/skills/gem-<이름>/SKILL.md`로 변환하고,
클로드는 각 스킬의 `description`을 보고 **지금 이 대화에 필요한 젬인지 스스로 판단**합니다.

---

## 기본 제공 젬

| 젬 | 하는 일 | 이런 말에 반응 |
|---|---|---|
| `email-writer` | 업무 이메일·회신 초안 | "메일 써줘", "정중히 거절", "독촉 메일" |
| `report-summarizer` | 임원 보고용 요약 | "요약해줘", "핵심만", "한 장으로" |
| `meeting-notes` | 회의록 + 액션아이템 | "회의록 정리", "녹취 풀어줘" |

---

## 좋은 젬을 쓰는 요령

1. **`description`에 공을 들이세요.** 클로드는 이 한 문장만 보고 자동 호출 여부를 정합니다.
   여러분이 실제로 칠 법한 말("메일 써줘")을 그 안에 직접 넣어두세요.
2. **규칙은 검증 가능하게.** "좋게 써라"(X) → "5문장 이내, 느낌표 금지"(O)
3. **출력 형식을 코드블록으로 박아두세요.** 재현성이 확 올라갑니다.
4. **예시 1개가 지시문 10줄보다 강합니다.**
5. 젬은 작게 쪼개세요. 만능 젬 하나보다 역할이 뚜렷한 젬 3개가 훨씬 잘 걸립니다.

## 클로드의 다른 "Gem 비슷한 것"들

이 저장소가 쓰는 스킬 말고도, 용도에 따라 골라 쓸 수 있습니다.

| 기능 | 제미나이로 치면 | 언제 쓰나 |
|---|---|---|
| **Skills** (이 저장소) | Gem | 상황에 따라 자동으로 꺼내 쓰고 싶은 역할 |
| **Projects** (claude.ai) | Gem + 지식 파일 | 웹/앱에서 자료 묶음과 함께 쓸 때 |
| **CLAUDE.md** | 시스템 지시 | 프로젝트 전체에 항상 적용할 규칙 |
| **Subagent** (`.claude/agents/`) | — | 별도 컨텍스트에서 독립 실행시킬 전문가 |
| **Slash command** (`.claude/commands/`) | 저장된 프롬프트 | 내가 직접 호출하는 정형 작업 |

Gem과 가장 결이 같은 건 **Skills**이고, 자동 호출·도구 사용·버전 관리(git)가 된다는 점에서 한 단계 위입니다.

# 블로그 자동화

매일 컴퓨터를 켜고 클로드 코드를 열면, 키워드 선정부터 완성 원고까지 **묻지 않고 3편**을 씁니다.

## 켜고 끄기

`blog.config` 한 파일이 전부입니다.

```bash
AUTO_MODE=auto      # auto(바로 씀) | ask(물어봄) | off(끔)
POSTS_PER_DAY=3
PLATFORM=naver      # naver | brunch
```

## 처음 한 번만: 폴더 신뢰

PC에서 이 폴더로 이동해 클로드 코드를 **한 번 실행**하고, 뜨는 신뢰 대화상자에 '예'를 누르세요.

```bash
cd totaldi
claude
```

이걸 해야 `.claude/settings.json`의 허용목록이 작동합니다. 안 하면 매번 명령 승인을 물어봅니다.
딱 한 번이면 됩니다.

---

## 매일 블로그 쓰는 법 — 세 가지 중 편한 걸로

### 방법 A. 그냥 클로드 코드 열고 아무 말이나 (제일 쉬움)

```bash
claude
```

세션이 열리면 훅이 이미 키워드를 뽑아 지시문을 대기시켜 둡니다.
여기서 **아무거나 한 마디** 치면 바로 3편 작성이 시작됩니다. `시작` 이든 `ㄱ` 이든 상관없습니다.

> 왜 한 마디가 필요한가: 클로드 코드는 사용자가 입력해야 한 턴이 돕니다.
> 훅은 밥상을 차려둘 뿐, 숟가락은 형님이 드셔야 합니다.

### 방법 B. 타이핑 0 — 바로가기 하나로

```bash
./scripts/blog-now.sh          # 맥 / 리눅스
scripts\blog-now.bat           # 윈도우 (더블클릭)
```

클로드 코드가 열리면서 **곧바로** 3편을 씁니다. 아무것도 안 쳐도 됩니다.

- 윈도우: `scripts\blog-now.bat` 우클릭 → 바로 가기 만들기 → 바탕화면에 두고 더블클릭
- 맥: `alias blog='~/totaldi/scripts/blog-now.sh'` 를 `~/.zshrc` 에 넣고 터미널에 `blog`

### 방법 C. 완전 무인 — 컴퓨터 켜면 글이 저장돼 있음

창도 안 열리고 백그라운드로 돌아 원고만 저장합니다.

```bash
./scripts/blog-now.sh --headless
```

**윈도우 — 작업 스케줄러 등록**
1. 시작 메뉴에서 '작업 스케줄러' 실행
2. 우측 '기본 작업 만들기' → 이름 `블로그 자동작성`
3. 트리거: **로그온할 때**
4. 동작: 프로그램 시작 → `C:\경로\totaldi\scripts\blog-now.bat`, 인수에 `--headless`

**맥 — 로그인 항목 등록**
시스템 설정 → 일반 → 로그인 항목 → `+` → `blog-now.sh` 추가

작성 결과는 `posts/.last-run.log` 에 남습니다.

## 동작 흐름

```
클로드 코드 실행
  └─ SessionStart 훅 → scripts/daily_blog.sh
       ├─ 오늘 3편 다 썼나? → 예: 조용히 종료 (중복 작성 안 함)
       └─ 아니오
            ├─ scripts/keyword_radar.py 로 키워드 3개 선정
            │    1) 구글 트렌드 실시간 RSS
            │    2) 네이버 데이터랩 API (키 있으면)
            │    3) keywords/bank.json 시드 뱅크 ← 항상 동작
            └─ 클로드에게 "blog-autopilot 스킬로 3편 써라" 지시
                 ├─ 시드 → 웹 검색으로 실검색 롱테일 키워드 확정
                 ├─ 수치·제도 검증 + 출처 확보
                 ├─ gem-blog-writer 문체 규칙으로 집필
                 ├─ style_check.py 전항목 통과할 때까지 수정
                 └─ posts/YYYY-MM-DD/01~03-*.md 저장
```

**독자 배분**: 40~50대 2편 + 60대 이상 실버 1편 (자동 로테이션)
**중복 방지**: `keywords/used.log`에 기록해 120일 내 재사용 차단, 테마도 분산

## 문체 검사기

젬의 규칙을 눈대중이 아니라 기계로 검증합니다. 자동 생산 공정에 강제로 들어가 있습니다.

```bash
python3 scripts/style_check.py posts/2026-09-16/*.md
```

검사 항목: 분량 / 짧은 문장 비율 / 긴 문장 비율 / 평균 문장 길이 /
**문장 길이 표준편차(리듬의 핵심 지표)** / 1문장 문단 / 같은 어미 5연속 / 어미 종류 /
AI 블랙리스트 표현 / 과장 부사 / 구체적 수치 개수 / '여러분' 남용 / 본인 경험 자리.

기준은 독자층에 따라 다릅니다. 실버 독자는 문장 35자 상한이 걸리므로
"긴 문장" 기준도 25자로 내려 잡습니다.

## 수동 실행

```bash
/blog-daily                     # 오늘치 자동 생산
/blog 국민연금 조기수령          # 주제 지정해 1편
python3 scripts/keyword_radar.py  # 키워드만 뽑아보기
```

## 트렌드 API 연결 (선택)

네이버 데이터랩을 쓰려면 [네이버 개발자센터](https://developers.naver.com)에서 앱을 등록하고
환경변수 2개만 넣으면 됩니다. 없어도 시드 뱅크로 돌아갑니다.

```bash
export NAVER_CLIENT_ID=...
export NAVER_CLIENT_SECRET=...
```

## 알아두실 점

- **네이버 블로그 자동 업로드는 안 됩니다.** 네이버가 외부 글쓰기 API를 열어두지 않아,
  완성 원고를 만드는 것까지가 한계입니다. 복사해서 붙여넣으세요.
- 원고에 `[여기에 본인 경험]` 표시가 1~2곳 들어갑니다. 지어낸 경험을 쓰지 않기 위한 장치이고,
  형님이 직접 채우면 글의 급이 확 올라갑니다.
- 검증 못 한 수치는 본문에서 빼고 글 끝 `[확인 필요]`에 모읍니다.

## 키워드 뱅크 늘리기

`keywords/bank.json`의 테마별 배열에 단어만 추가하면 됩니다. 현재 11개 테마 × 2개 독자층 = 220개.
